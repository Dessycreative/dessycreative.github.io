How I work

Source → Model → Test → Reconcile → Serve

Five steps I follow on every build, each proved by a different team. Happy to walk through any of them.

01 Source

Messy systems in

Operations

ERP transactions and physical stock counts land every morning, ready to model. Before that, managers rebuilt the same operational reports in Excel every week. A Power BI app replaced them.

02 Model

One star schema per subject area

Finance

dbt in a Microsoft Fabric Warehouse takes SQL Server sources through staging into conformed dim_/fact_ marts, then a thin semantic layer built for Direct Lake. For finance that became a P&L star schema. Every change goes through branches and pull requests.

03 Test

Catch it before finance does

Finance

Reconciling the full-year P&L line by line surfaced a currency-conversion defect in an upstream dbt transformation. It was fixed in the pipeline, not patched over in DAX.

04 Reconcile

The totals tie out

FinanceOperations

Period-end AP accruals reconciled with 0 unexplained lines. Physical stock against system stock: 0.10% quantity variance, like for like.

05 Serve

Models people actually use

ProcurementCommercial

Direct Lake semantic models with reusable calculation-group time intelligence and role-playing dimensions, so every report on top shows the same numbers. An audit of a legacy model found most of its measures unused, flagged non-additive metrics, and caught a date rule that would have broken at the start of the next financial year. Also: a weekly sales forecast that leaves out bank-holiday weeks.

Play

Find the bad join

A report total that doesn't tie out to the ledger. Can you spot why?

Two orders each have two deliveries. Joining orders to deliveries before summing counts those orders twice, so the report shows €720 against a ledger of €400. Collapse deliveries to one row per order first and the totals are reconciled.
